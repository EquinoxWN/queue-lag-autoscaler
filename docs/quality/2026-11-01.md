# Quality check 2026-11-01

The ten engineering rules, checked against the M1 code (written 2026-11-14, file name kept the same
as the other repositories).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Every call can fail | pass | The only outbound call is the metrics fetch (`internal/source/source.go` `HTTP.Offsets`): per-attempt `http.Client.Timeout` (default 5 s, `-timeout`), 3 attempts with doubling backoff (200 ms, 400 ms) for network errors, 429 and 5xx only, context-aware waits, 8 MiB body cap. Tests: `TestHTTPTimeout`, `TestHTTPGivesUpAfterAttempts`, `TestHTTPClientErrorIsNotRetried`, `TestHTTPParseErrorIsNotRetried`, `TestHTTPContextCancelStopsBackoff`, `TestHTTPBodyLimit`. The `run` loop stops after `-max-failures` consecutive failed ticks (`TestRunStopsAfterConsecutiveFailures`) and reports each failure on stderr. Ignored errors are commented: closing read-only files and response bodies, and draining up to 4 KiB of an error body. |
| 2 | Writes safe to retry | N/A | M1 writes nothing outside stdout: it reads offsets and prints JSON lines. The in-process broker is a test double. Acting on Kubernetes (scale subresource, an idempotent "set replicas to N") is M3. |
| 3 | No race conditions | pass | `Controller.Tick` holds a mutex over the estimators and remembered rates; the broker locks all state. `TestConcurrentTicks` (8 goroutines x 50 ticks with produce and consume); `go test -race` runs in CI (no cgo locally). |
| 4 | Don't trust the clock | pass | Rate intervals use `time.Time.Sub` on values from `time.Now` (monotonic reading kept; the controller converts to UTC only for the printed `at`, after the estimator has the original). Non-positive intervals are ignored (`TestNonPositiveElapsedKeepsPreviousRates`). Printed times are UTC (`TestTwoTicksMeasureAndDecide` checks the location). The simulation uses a virtual clock. |
| 5 | Read before changing | pass | No environment variables are read; configuration is flags and the JSON file, both listed in the README. The kafka_exporter metric names and the `kafka-consumer-groups.sh` columns are the ones those tools print; the describe parser locates columns by header name. Paths in docs exist (`examples/*`, `scripts/vulncheck.sh`, `internal/lag/testdata/kafka_exporter.prom`). |
| 6 | Never break compatibility | pass | First version of the config and output formats. Optional config fields have defaults (`smoothing`, `workers`, `worker_rate`, `busy_lag`, `cap_to_partitions`); unknown fields are refused so a typo cannot be silently ignored. Output fields are documented in the README. |
| 7 | One source of truth | pass | Offsets come only from the source; the estimator keeps the previous snapshot (replaced every tick) and the remembered capacity (replaced by each stable busy interval, ADR 0002). Go 1.26.10 appears in CI, README and `.tmp/check.sh`; `go.mod` says `go 1.26.0` (minimum language version). |
| 8 | No secrets, validate input | pass | No secrets in the repo; example consumer ids are made up. URLs must be http(s) with a host and no user info. Every input is validated: group (`[A-Za-z0-9._-]{1,255}`) and topic (`{1,249}`) names, partitions, offsets, integral finite metric values, label syntax, duplicate partitions, the `LAG` column cross-check, 8 MiB snapshots, 1 MiB configs with 1,000 groups, policy ranges (target 1 s to 24 h, 1 to 10,000 workers, finite rates), interval 1 s to 1 h. Error tables in `describe_test.go`, `prom_test.go`, `config_test.go`, `scale_test.go`. |
| 9 | Tests that can fail | fixed | No skips, no tautologies. Hand mutants: 12 of 14 killed at first run; one survivor killed by a new test case, one mutant did not compile and was rewritten (table). |
| 10 | Re-verify | pass | `bash .tmp/check.sh`: gofmt and vet clean, `tests passed: 65`, demo `verify:` all true, vulncheck only the allowlisted GO-2026-6859, `queue-lag-autoscaler: OK`, `CHECK PASS`. CI not yet run. |
